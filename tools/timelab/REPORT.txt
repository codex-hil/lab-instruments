Ograniczenia i nieudane warianty:
- To krótka walidacja funkcjonalna, nie wielogodzinny test stabilności.
- Wine built-in GDI+ dawał białe PNG; natywny GDI+ Windows 10 rysował bez tekstu.
  Sprawdzona konfiguracja używa gdiplus.dll x64 1.1.7601.18852 z oficjalnego
  pakietu KB3065979. SHA256 DLL zapisano w evidence/final-sha256.txt.
- Minimalny ręcznie utworzony TIM powodował awarię. Konwerter używa pełnego
  nagłówka przykładu producenta. Pole instrumentu HP 5370A/B pochodzi z szablonu;
  nie oznacza przyrządu ani fizycznego pomiaru. Dane są syntetyczne.
- Natywnego dialogu importu ASCII nie testowano; testowano konwerter 1 Hz -> TIM.
- Tunel X11 przez SSH został ustanowiony, ale lokalne :0 na Optiplex odrzuciło
  połączenie sesji narzędziowej z powodu xauth. Interaktywne GUI przez SSH
  wymaga terminala z dostępem do lokalnego serwera X i pozostaje NOT_VERIFIED
  end-to-end. GUI na Xvfb na Dell jest PASS.
- Nie konfigurowano ZeroTier, TSERVE, aparatury ani sterowników przyrządowych.
- Nie wykonywano instalacji pełnego Windows ani .NET. Pakiety Microsoftu
  wypakowano tylko do wydzielenia GDI+. Python Windows był narzędziem dekodowania.

Zachowano instalator, sumy kontrolne, logi udanych i nieudanych prób, porównania
AllanTools, źródłowe dane syntetyczne, skrypty i wykresy. Python naukowy jest
w osobnym venv. Nie zmieniano konfiguracji Vivado/Quartus/Docker/HIL, VPN ani
przekierowań licencyjnych. Nie dodano usług sieciowych. Wine nie działał jako root.
