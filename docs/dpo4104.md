# Tektronix DPO4104 — handoff dla kolejnych wątków

2026-10-30: zidentyfikowano fizyczny DPO4104, serial **C022184**, firmware
`CF:91.1CT FV:v2.48`, LAN **192.168.2.10:4000**. IP jest wskazówką DHCP,
nie tożsamością. Historyczny DMM7510 miał ten sam adres; nie używać starego
wpisu DMM do tego urządzenia. Każde połączenie wymaga sprawdzenia modelu i serialu.

Profil `dpo4104` korzysta ze wspólnego drivera oscyloskopów Tektronix:
`identify`, `read frequency`, `read vpp`, kanały 1–4. Nie duplikujemy SCPI.
Transport TCP: LF, padding CR jak MSO4104. Numer seryjny wpisano w gotową
konfigurację `examples/dpo4104.json`.

## Użycie

Uruchamiać z checkoutu zawierającego profil DPO4104:

```sh
python3 -m labinstruments identify --config examples/dpo4104.json --device dpo4104
python3 -m labinstruments read --config examples/dpo4104.json --device dpo4104 --operation vpp --channel 1
python3 -m labinstruments read --config examples/dpo4104.json --device dpo4104 --operation frequency --channel 1
```

API Python: `Driver(transport, 'dpo4104', 'C022184')`, następnie `identify()`
i `read('vpp', 1)` / `read('frequency', 1)`. Jednostki V oraz Hz; wynik jest
tekstem SCPI. Wartość około `9.9E37` oznacza nieważny pomiar, nie realny sygnał.
Kanał musi być wyświetlany i mieć odpowiedni sygnał/skale. Profil sam ich nie zmienia.

## Koordynacja i skutki uboczne

Na Optiplex używać kooperatywnego flock
`/home/codex-hil/.cache/dpo4104-C022184.lock` przez całą sesję sprzętową.
Nie kasować locka i nie omijać zajętego urządzenia inną ścieżką. Przykład:

```sh
flock -n /home/codex-hil/.cache/dpo4104-C022184.lock \
  python3 -m labinstruments identify --config examples/dpo4104.json --device dpo4104
```

Sam Driver nie pozyskuje tego locka; skrypt obejmujący kilka operacji musi
utrzymać jeden lock przez cały test. `read` zmienia HEADER oraz typ/źródło
IMMED measurement. Jeżeli zachowanie ustawień jest wymagane, zapisać te pola
przed testem i odtworzyć w finally. Nie zmienia podstawy czasu, skali, triggera,
RUN/STOP ani wyświetlania kanałów. Nie wykonywać resetu ani autoset bez potrzeby.

## Sprawdzenie fizyczne i ograniczenia

[Surowy raport](../reports/dpo4104-2026-10-30.json): ID PASS, odczyty CH1 PASS,
przywrócenie HEADER i IMMED source/type potwierdzone. CH1 zwrócił 40 mVpp
oraz 285.7143 MHz; nie znamy podłączonego sygnału, więc nie jest to dowód
poprawności metrologicznej. CH2–4 były niewyświetlane, pozostawiono je bez zmian.

Nie wykonano kalibracji/porównania ze wzorcem ani testów kanałów 2–4 na sprzęcie.
Pobieranie waveformów i FRA dla tego modelu nie są częścią tego profilu;
rozszerzenie FRA istnieje na osobnej gałęzi i wymaga odrębnej integracji/odbioru.
Nie oznaczamy całej możliwości pomiarowej jako TRUSTED na podstawie samego ID.
